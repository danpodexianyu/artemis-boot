## 使用说明
1. 验收标准仅描述外部可观测行为，禁止填写代码实现细节。
2. 故事点估算采用斐波那契数列：1,2,3,5,8。
3. 阻塞依赖必须状态为Done才可启动开发；参考依赖仅作查阅，不阻塞任务执行。
4. 推荐每个UserStory拆分3个子任务：编码实现、单元测试&接口自测、文档更新。
5. Git Commit规范：[ART-{任务编号}] type: description
   type可选值：feat(新增功能) / fix(缺陷修复) / docs(文档更新) / refactor(代码重构) / test(新增测试)
6. 复制内容直接粘贴至Jira描述框，使用Markdown模式，不要从Word复制，避免格式错乱。

## DOD（Definition of Done - 完成定义）
> 分为两个阶段：开发完成(可提CR)、验收完成(Story可关闭)

### 开发完成（开发自测通过，具备提交CR条件）
- 开发编码完成，代码提交至feature分支，完成开发者自审
- 编写单元测试，核心逻辑覆盖，执行 mvn test 全部通过
- 补充OpenAPI注解，接口文档可正常访问，模型、接口信息展示正确
- 本地全部验收标准项自测验证通过

### 验收完成（评审&测试通过，Story允许关闭）
- 提交Pull Request，完成代码评审CR，评审意见全部闭环
- 更新项目README，记录本阶段新增能力、包结构变更
- 不存在阻断级Bug；低风险缺陷已单独登记至Jira缺陷单
